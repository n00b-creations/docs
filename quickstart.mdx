The repository currently contains the Mintlify documentation shell for CYBER-OS. Use this workflow to validate changes locally before publishing them.

## Prerequisites

Before you begin, install:

- Node.js and npm
- The Mintlify CLI
- Git

You also need access to the `n00b-creations/docs` repository if you intend to publish changes.

## Local validation

<Steps>
  <Step title="Install the Mintlify CLI">
    Install the CLI globally:

    ```bash
    npm i -g mint
    ```
  </Step>
  <Step title="Start the local preview">
    From the documentation repository root, where `docs.json` is located, run:

    ```bash
    mint dev
    ```

    Open the local preview at `http://localhost:3000`.
  </Step>
  <Step title="Verify the documentation tree">
    Confirm that the landing page and navigation load without errors. Check that internal links resolve and that code blocks render correctly.
  </Step>
</Steps>

## Repository checks

Before committing documentation changes, verify:

- `docs.json` remains valid JSON and matches the intended navigation.
- Every navigation page exists as an MDX file.
- Internal links target existing pages.
- Commands and configuration examples match the current implementation.
- No placeholder content remains in pages being presented as operational documentation.

## Publishing

The Mintlify deployment is configured to source documentation from GitHub and deploy from `main`. Push reviewed changes to the configured deployment workflow rather than treating the local preview as production.

## Troubleshooting

### The local preview does not start

Run the CLI update and retry:

```bash
mint update
mint dev
```

### A page returns 404

Confirm that the page path is present in `docs.json` navigation and that the corresponding MDX file exists.

### A navigation entry is broken

Check the navigation tree and compare every page reference with the actual MDX path. Avoid adding navigation entries for pages that have not been created.
