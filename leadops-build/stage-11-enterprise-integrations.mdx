# Stage 11 — Enterprise Integrations & LeadOps Ecosystem

Stage 11 connects the production LeadOps core to the external business systems that generate, enrich, communicate with, schedule, monetize, and report on leads.

      ↓

## Connector contract

External providers should implement a common contract:

```ts
export interface IntegrationAdapter {
  connect(): Promise<void>;
  disconnect(): Promise<void>;
  health(): Promise<IntegrationHealth>;

  capabilities(): IntegrationCapability[];

  handleEvent(event: ExternalEvent): Promise<void>;

  sync(request: SyncRequest): Promise<SyncResult>;
}
```

This prevents provider-specific behavior from leaking into the core LeadOps domain.

## Canonical event model

LeadOps should translate provider-specific events into canonical events:

```text
provider.event
      ↓
verification
      ↓
normalization
      ↓
canonical event
      ↓
LeadOps event bus
```

Example:

```ts
interface LeadCreatedEvent {
  type: "lead.created";

  eventId: string;
  tenantId: string;

  occurredAt: string;

  leadId: string;

  source: {
    provider: string;
    externalId: string;
  };
}
```

## Conflict resolution

Provider data must not automatically overwrite authoritative LeadOps state.

Use:

```
Policy
  ↓
System-of-record designation
  ↓
Field-level authority
  ↓
Timestamp/version comparison
  ↓
Conflict resolution
  ↓
Audit
```

Example field authority:

```yaml
lead:
  phone:
    authority: crm
  lifecycleStage:
    authority: leadops
  consent:
    authority: leadops
  appointment:
    authority: calendar
  revenue:
    authority: revenue-system
```

## Integration permissions

A connector receives only the capabilities it needs.

Example:

```yaml
integration:
  capabilities:
    - lead.read
    - lead.create
    - activity.write

  prohibited:
    - tenant.settings.write
    - policy.modify
    - audit.delete
```

This preserves the Stage 9 control-plane authority boundary.

## Integration database

```sql
CREATE TABLE integrations (
    id UUID PRIMARY KEY,
    tenant_id UUID NOT NULL,

    provider TEXT NOT NULL,
    category TEXT NOT NULL,

    status TEXT NOT NULL,

    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    UNIQUE (tenant_id, provider)
);
```

Credentials should be referenced through the secrets subsystem rather than stored directly in this table.

## Stage 11 acceptance criteria

- Provider adapters cannot bypass tenant isolation.
- Provider credentials are stored through the secrets subsystem.
- External events are verified before entering the event bus.
- Provider events normalize into canonical LeadOps events.
- Synchronization is checkpointed and resumable.
- Duplicate events are idempotent.
- Conflicts follow explicit field/system authority rules.
- Connector health is observable.
- Integration permissions are capability-scoped.
- Every synchronization and external action is auditable.
- Provider failures do not corrupt LeadOps system-of-record state.
- Connectors can be installed and disabled without modifying the core domain.
